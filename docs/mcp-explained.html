How the FocusTrack MCP server works

Plain-language guide to what was built, where it lives, and how an AI connects to create / edit / delete your tasks.

One-line summary: MCP is a small API on your Vercel app. An AI (Cursor, Claude, etc.) calls tools like create_task over HTTP. Those tools write to the same Neon Postgres database your website uses.

1. What is MCP?

MCP = Model Context Protocol. It is a standard way for AI apps to use tools (functions) on a server you control.

  • Your website is for humans (buttons, pages).
  • Your MCP endpoint is for AIs (JSON tool calls).

Opening /api/mcp in a browser looks empty or odd — that is normal. It is not a webpage; it is an API the AI speaks to.

2. Big picture flow

You (or Cursor AI) │ │ HTTP POST + optional Bearer token │ "please call create_task with these fields" ▼ https://task-two-pi-52.vercel.app/api/mcp │ │ Next.js route → mcp-handler → tool code ▼ lib/mcp/tools.ts (create_task, list_tasks, …) │ │ Drizzle ORM ▼ Neon Postgres (same DATABASE_URL as the FocusTrack UI) │ ▼ Website at https://task-two-pi-52.vercel.app/ shows the updated tasks
1
AI decides it needs a tool Example: “Add a task for tomorrow under Projects.”
↓
2
AI calls your MCP URL POST https://task-two-pi-52.vercel.app/api/mcp with a tool name + arguments.
↓
3
Vercel runs the route app/api/mcp/route.ts → lib/mcp/handler.ts → registers tools from lib/mcp/tools.ts.
↓
4
Tool talks to the database Same Neon DB as the Next.js app. Insert / update / delete rows.
↓
5
Result goes back to the AI Usually JSON text (the created row, the list, an error, etc.). You refresh the site and see it.

3. How it was created (two layers)

A. Docker MCP (first version)

Under mcp/ there is a standalone Express server using the official MCP TypeScript SDK. It listens on port 3100 and can run in Docker. Useful on your own VPS — not what Vercel runs.

B. Vercel MCP (what you use now)

Vercel does not run that Docker process. So the same tools were wired into the Next.js app with Vercel’s mcp-handler package:

File Job
lib/mcp/tools.ts All CRUD tools (tasks, projects, categories, topics, time entries)
lib/mcp/handler.ts Builds the MCP server + optional API key check
app/mcp/route.ts Public URL: /mcp
app/api/mcp/route.ts Public URL: /api/mcp (what most AIs look for)
Until those files were committed and pushed to main, Vercel still returned 404. Deploy succeeded after push — that is why the AI finally can connect.

4. How anyone connects (Cursor / other AI)

The client needs:

  1. The MCP URL (Streamable HTTP)
  2. Optional Bearer token if MCP_API_KEY is set on Vercel
{
  "mcpServers": {
    "todo": {
      "url": "https://task-two-pi-52.vercel.app/api/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_MCP_API_KEY"
      }
    }
  }
}

Put that in Cursor MCP settings (or paste the URL + token to your AI host). After connect, the AI can list tools, then call them.

5. Auth flow

A
MCP_API_KEY set on Vercel Requests without Authorization: Bearer … get 401. Matching key → tools allowed.
B
Key not set Endpoint is open (fine for quick tests, risky in public).

6. Example tool call (what the wire looks like)

Simplified idea of what the AI sends:

POST /api/mcp
Authorization: Bearer YOUR_MCP_API_KEY
Content-Type: application/json
Accept: application/json, text/event-stream

{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "list_categories",
    "arguments": {}
  }
}

Server answers with tool result JSON (categories from your DB).

9. Common confusion

What people try What it actually is
Open /api/mcp in Chrome Not a dashboard — AI protocol endpoint
Expect Docker on Vercel Vercel runs serverless route handlers, not your Docker container
404 before push Code only existed locally until it was on main
401 without token MCP_API_KEY is set — send Authorization: Bearer …
